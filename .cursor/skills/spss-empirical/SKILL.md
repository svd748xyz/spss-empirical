# SPSS 实证分析

统计数字只来自 SPSS 输出，不补写未跑出的显著性。

先确定安装目录：读取本 Skill 目录里的 `package_root.txt`，用其中的绝对路径作为工作目录。解释器读取同目录的 `python_exe.txt`。这两个文件不存在时，使用同时包含 `spss_agent` 与 `.cursor/skills/spss-empirical` 的目录，解释器用 `python`。之后所有命令都在该目录执行，形式为 `"<python_exe.txt 中的路径>" -m spss_agent ...`。没有这个目录时，先运行安装脚本 `install.ps1`，不要改用其他统计软件。

## 流程

复制下面的清单并逐项完成：

```
- [ ] 1. 检测 SPSS
- [ ] 2. 扫描用户指定的项目文件夹
- [ ] 3. 分轮澄清，一次只问关键缺口
- [ ] 4. 写出完整分析方案并等待用户回复「开始」
- [ ] 5. 执行 SPSS，生成 Word 与过程文件
```

### 1. 检测 SPSS

```bash
python -m spss_agent detect
```

失败时把命令的原文告诉用户，并停止。不要改用其他软件假装已经完成 SPSS 分析。

### 2. 扫描材料

项目文件夹由用户指定，且必须可读写。建议含数据（`.sav` / `.xlsx` / `.csv`）、问卷、参考文献（可选）和 `需求说明.txt`。

```bash
python -m spss_agent scan "<项目文件夹>"
```

先读 `需求说明.txt`、问卷和扫描到的列名。参考文献只用于理解构念，不编造引用。

### 3. 澄清

一次最多问 4 个还没确定的问题，按这个顺序：研究问题与因变量、量表题项如何合成、分组变量的取值、方法取舍（相关/回归/差异/中介/调节）。已经写明的内容直接采用，不要重复追问。

方法选择见 [reference.md](reference.md)。不确定就问。做不到的分析直接说明，不要换一套结果充数：

- 结构方程、验证性因子、AMOS、多层模型
- Hayes PROCESS 与 Bootstrap 置信区间。中介报告路径系数和 Sobel 检验，不写 Bootstrap 区间。并行中介把 `m` 写成数组；链式中介把 `structure` 写成 `serial`，数组顺序就是链条顺序。有调节的中介用 `moderated_mediation`

### 4. 完整分析方案

把方案写成项目文件夹里的 `分析方案.json`，字段见 [reference.md](reference.md)。在对话里用中文复述：数据文件、样本量是否尚未读取、变量和量表、每一项分析、不会做的分析、输出位置。明确写：未回复「开始」之前不会调用 SPSS。

用户回复「开始」后才进入第 5 步。若用户改方案，更新 JSON 后再次等待「开始」。

### 5. 执行

先确认本机没有正在运行的 `stats.exe`。然后：

```bash
python -m spss_agent run "<项目文件夹>" --plan "<项目文件夹>/分析方案.json"
```

成功时命令打印 Word 路径。同时查看项目下最新的 `spss_output/<时间>/run_manifest.json`。向用户说明：

- 主报告：项目根目录 `实证分析报告.docx`，以及该次运行目录中的副本
- 语法 `analysis.sps`、生产作业 `analysis.spj`、查看器 `viewer.txt`、`oms/`、`数据说明.md`、`analysis_plan.json`

命令若因语法错误退出，打开查看器中的 `Error #` 原文再决定是否修改方案。不要手工填上缺失的 p 值。报告里的授权提示若写明临时使用期，照实告诉用户。

## 报告约束

- 交给读者的 Word 只写方法、结果和简要讨论。软件路径、授权剩余天数、OMS 和本地过程文件路径写在对话里，不写进正文
- 方法按论文来写：样本、变量如何计分、用了什么检验。不要写“本工具不支持”或安装目录
- 结果先用一段话写出读到的结论，再给表，并写“详见表”
- 三线表由 `spss_agent.report` 生成：A4，表题在顶线上方并带表序和样本量，只有顶线、栏目线和底线，没有竖线。同一类结果合成一张表：人口学用项目、分类、例数、构成比；同一因变量的 t 检验和方差分析合成一张单因素表；多个量表的信度合成一张 α 表。题项超过 15 个时，正文不逐题铺 CITC
- 回归表分列未标准化系数（B、标准误）和标准化系数，模型 R²、调整 R² 和 F 放在表下注释。P 用三位小数并保留前导零，小于 0.001 写作 `<0.001`
- 假设未检验或未满足时，保留程序写明的处理（如方差不齐用校正 t、VIF、Sobel 而非 Bootstrap）
- 横断问卷的讨论不得升级为因果结论
